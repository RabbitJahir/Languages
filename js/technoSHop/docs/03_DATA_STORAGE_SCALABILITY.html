DATA STORAGE & SCALABILITY

💾 Current Storage Implementation: localStorage

What is localStorage?

localStorage is a browser API that allows JavaScript to store data persistently on the user's device. Unlike session variables (which clear on browser close), localStorage persists indefinitely until explicitly cleared.

Current Data Model

Blood God's Vault uses localStorage to store four main data structures as JSON strings:

Storage Key Data Type Example Structure Max Size
shop_items Array[4] of Objects [{id, name, price, quantity, ...}] ~500 bytes
cart Array of Objects [{id, qty, name, img}] ~1 KB (per user)
orders Array of Objects [{id, qty, name, img, price}] ~5 KB (per user)
session Object {username, role} ~200 bytes

localStorage Example Data

// shop_items key stores active inventory { "shop_items": [ { "id": "one", "name": "Crown of the Blood God", "price": 1050, "desc": "...", "img": "technoblade-crown.jpeg", "badge": "Authenticated Relic", "quantity": 8 }, ... ] } // cart key stores current shopping session { "cart": [ {"id": "one", "qty": 2, "name": "Crown of the Blood God", "img": "..."}, {"id": "three", "qty": 1, "name": "Sword of Legends", "img": "..."} ] } // orders key stores completed purchases { "orders": [ {"id": "two", "qty": 1, "name": "Cape of the Blood God", "img": "...", "price": 1000}, {"id": "four", "qty": 1, "name": "Potato of Power", "img": "...", "price": 1000} ] } // session key stores authentication { "session": {"username": "username", "role": "user"} }

⚠️ Limitations of Current localStorage Approach

1. Data Isolation Per Browser/Device

Each user's browser maintains its own copy of shop_items. If the admin updates prices on one computer, another user's browser doesn't see the update until they refresh or revisit the page.

2. No Inventory Synchronization

Multiple users can purchase the same item simultaneously without inventory conflicts. There's no locking mechanism to prevent overselling. For example, if an item has 3 units left and 3 different users add 1 to their cart, all could proceed without knowing stock is depleted.

3. Vulnerable to Tampering

Users can open browser DevTools and directly modify localStorage:

// In browser console, user could do: localStorage.setItem('shop_items', JSON.stringify([ {id: "one", name: "Crown", price: 1, quantity: 999999} ])) // This would show items as $1 permanently for that user!

4. No Persistent Purchase Records

Orders are stored locally, not on a server. If a user clears their browser data or uses a different device, their "purchases" are lost. There's no business record of transactions.

5. Storage Quota Exceeded Risk

With thousands of items or users with large order histories, the 5-10 MB limit could be exceeded, causing the application to fail.

6. No Multi-User Coordination

Admin updates to inventory or pricing won't automatically propagate to other users. Each user sees prices and availability as they were when they loaded the page.

🚀 Scaling Strategy: Migration to Backend Database

Architecture Overview

Client (Browser)
↓ (HTTP/HTTPS requests)

↓ (SQL queries)

↓ (Persistent storage)
Data Backup & Replication (multiple servers)

📋 Step-by-Step Migration Plan

Phase 1: Backend API Setup

Required Components:

  • Web Server: Node.js with Express.js (or Python Flask/Django)
  • Database: PostgreSQL or MongoDB
  • Authentication: JWT tokens or session-based auth
  • API Endpoints: RESTful routes for all operations

Example API Endpoints:

// Authentication POST /api/auth/login Request: {username, password} Response: {token, username, role} POST /api/auth/logout Request: {token} Response: {success: true} // Items (Products) GET /api/items Response: [array of all items] PUT /api/items/:id Request: {price, quantity} (admin only) Response: {success, updatedItem} // Cart Operations GET /api/cart Request: {token} Response: [array of user's cart items] POST /api/cart/add Request: {token, itemId, quantity} Response: {success, updatedCart} POST /api/cart/remove Request: {token, itemId} Response: {success, updatedCart} // Orders (Purchases) POST /api/orders/checkout Request: {token, cartItems} Response: {success, orderId, order} GET /api/orders Request: {token} Response: [array of user's orders]

Phase 2: Database Schema

Core Tables (SQL Example):

-- Users Table CREATE TABLE users ( id INT PRIMARY KEY AUTO_INCREMENT, username VARCHAR(50) UNIQUE NOT NULL, password VARCHAR(255) NOT NULL, -- MUST be hashed! role ENUM('user', 'admin') DEFAULT 'user', created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Items Table CREATE TABLE items ( id VARCHAR(50) PRIMARY KEY, name VARCHAR(255) NOT NULL, description TEXT, price INT NOT NULL, quantity INT NOT NULL, image_url VARCHAR(255), badge VARCHAR(100), created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP ON UPDATE CURRENT_TIMESTAMP ); -- Cart Table (temporary) CREATE TABLE cart ( id INT PRIMARY KEY AUTO_INCREMENT, user_id INT NOT NULL, item_id VARCHAR(50) NOT NULL, quantity INT NOT NULL, added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (user_id) REFERENCES users(id), FOREIGN KEY (item_id) REFERENCES items(id) ); -- Orders Table (permanent records) CREATE TABLE orders ( id INT PRIMARY KEY AUTO_INCREMENT, user_id INT NOT NULL, item_id VARCHAR(50) NOT NULL, quantity INT NOT NULL, price_at_purchase INT NOT NULL, ordered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (user_id) REFERENCES users(id), FOREIGN KEY (item_id) REFERENCES items(id) );

Phase 3: Frontend Refactoring

Replace localStorage calls with API calls:

Current (localStorage):

function getItems() { const items = localStorage.getItem("shop_items"); return items ? JSON.parse(items) : DEFAULT_ITEMS; }

Updated (API):

async function getItems() { try { const response = await fetch('/api/items'); const items = await response.json(); return items; } catch (error) { console.error('Failed to fetch items:', error); return []; } } // Usage example: const items = await getItems(); renderShop(items);

Phase 4: Authentication Upgrade

Replace hardcoded credentials (login.js):

// OLD: Hardcoded credentials in JavaScript const USERS = { rabbit: { password: "rabbit", role: "admin" }, username: { password: "password", role: "user" } }; // NEW: Server-side validation with JWT async function login(username, password) { const response = await fetch('/api/auth/login', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ username, password }) }); const data = await response.json(); if (data.token) { localStorage.setItem('token', data.token); // Store JWT token localStorage.setItem('user', JSON.stringify(data.user)); window.location.href = data.role === 'admin' ? 'admin.html' : 'index.html'; } else { showError(data.message); } }

🔄 Data Synchronization Strategy

Real-Time Updates Using WebSockets

For production scales, implement WebSocket connections to push updates to all connected clients:

// Client side const socket = io('http://server.com'); // Listen for inventory updates socket.on('itemUpdated', (item) => { console.log('Item updated:', item); // Update local state and re-render updateItemDisplay(item); }); // Server side (Node.js + Socket.IO example) io.on('connection', (socket) => { // When admin updates price, broadcast to all clients socket.on('adminUpdateItem', (itemId, newData) => { // Validate and update database... io.emit('itemUpdated', updatedItem); // Broadcast to ALL clients }); });

🔒 Security Improvements in Migration

  • Password Hashing: Use bcrypt to hash passwords (never store plaintext)
  • JWT Tokens: Stateless authentication instead of localStorage sessions
  • HTTPS: Encrypt all data in transit
  • Input Validation: Validate all API inputs server-side
  • Rate Limiting: Prevent brute-force attacks on login endpoint
  • CORS: Restrict API access to authorized domains
  • Audit Logging: Track all admin actions and transactions
  • Payment Security: PCI-DSS compliance for transactions
