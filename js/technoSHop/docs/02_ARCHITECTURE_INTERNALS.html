📋 File-by-File Breakdown

shared.js - Core Utility Module

Purpose: Central hub for all shared functions used across the application.

Key Data Structures:

  • DEFAULT_ITEMS - Initial inventory array with 4 relics
  • USERS (defined in login.js) - Hardcoded user credentials

Core Functions:

Authentication & Sessions:

  • getSession() - Retrieves current user session from localStorage
  • requireAuth(role) - Security check; redirects if not authenticated
  • logout() - Clears session and redirects to login

Item Management:

  • getItems() - Retrieves shop inventory from localStorage
  • saveItems(items) - Persists inventory changes to localStorage

Cart Operations:

  • getCart() - Retrieves user's current shopping cart
  • saveCart(cart) - Saves cart contents to localStorage

Order Management:

  • getOrders() - Retrieves user's completed purchases
  • saveOrders(orders) - Saves purchase history to localStorage

Utilities:

  • formatPrice(p) - Formats numbers as USD currency (e.g., "1,000")

login.js - Authentication Module

Purpose: Handles user login and credential validation.

Execution Flow:

  1. IIFE (Immediately Invoked Function Expression) checks for existing session on page load
  2. If session exists, auto-redirects to appropriate page (admin.html or index.html)
  3. Form submission event listener validates credentials against USERS object
  4. On success: Creates session object and redirects based on role
  5. On failure: Displays error message and clears form

Hardcoded Credentials:

Username Password Role
rabbit rabbit admin
username password user

user.js - Shop Interface Module

Purpose: Manages the user shopping experience - rendering items, cart operations, and purchases.

Initialization:

  • requireAuth("user") ensures only authenticated users can access
  • init() function sets up event listeners and renders initial state
  • Modal event delegation for cart interface

Core Functions:

Rendering:

  • renderShop() - Generates product cards with stock status, pricing, and cart controls
  • Shows "SOLD OUT" overlay when quantity ≤ 0
  • Displays in-cart badges showing current quantity

Shopping Cart:

  • changeCart(id, delta) - Adds/removes items from cart (delta = ±1)
  • updateCartCount() - Updates cart badge with total items + orders
  • openCart() - Displays modal with cart items and purchase history
  • closeCart() - Closes cart modal

Pricing:

  • incrementPrice(id) - Increases item price by $50 and saves
  • Includes "bumped" animation on price update

Event Handling:

  • handleShopClick(e) - Delegated event handler for all shop buttons
  • Routes clicks to appropriate function based on button class

admin.js - Admin Dashboard Module

Purpose: Provides admin interface for managing prices and inventory quantities.

Initialization:

  • requireAuth("admin") restricts access to admin users only
  • renderAdmin() populates all item cards on page load

Core Functions:

Rendering:

  • renderAdmin() - Creates editable form cards for each item with:
  • Image display with badge
  • Number inputs for price (step: 50) and quantity
  • Save button to persist changes

Data Persistence:

  • saveItem(id) - Saves price and quantity updates to localStorage
  • Validates input values are non-negative numbers
  • Updates visual stock display
  • Shows success toast notification

Notifications:

  • showToast(message) - Displays temporary success notification
  • Auto-hides after 2 seconds

💾 localStorage Structure

The application uses four localStorage keys to persist data:

Key Data Type Purpose Format
shop_items Array of Objects Current inventory with prices and quantities JSON array: [{id, name, price, quantity, ...}]
cart Array of Objects User's current shopping cart JSON array: [{id, qty, name, img}]
orders Array of Objects User's purchase history JSON array: [{id, qty, name, img, price}]
session Object Current user authentication info JSON object: {username, role}

🔐 Security Architecture

Authentication Mechanism:

  • Credentials hardcoded in JavaScript (SECURITY WARNING: Not suitable for production)
  • Session stored as JSON in localStorage (accessible to JavaScript only)
  • requireAuth() function acts as gatekeeper for protected pages

Authorization:

  • Role-based access control (RBAC): "admin" vs "user"
  • Admin page checks for admin role; redirects non-admin users
  • User page checks for user role; redirects non-user users
⚠️ Security Note: This is a front-end demonstration. In production, credentials should be validated on a secure backend server, not hardcoded in JavaScript. All sensitive operations should involve server-side verification.

🎯 Entry Points

Login Page (login.html)

  • First Point: Public landing page accessible to anyone
  • Auto-redirect: Existing sessions auto-redirect to appropriate page
  • Script Load: Only login.js is loaded (smallest initial payload)

User Shop (index.html)

  • Protected: Requires authentication with "user" role
  • Scripts: Loads shared.js first (utilities), then user.js (shop logic)
  • Initialization: init() function called after auth check

Admin Dashboard (admin.html)

  • Protected: Requires authentication with "admin" role
  • Scripts: Loads shared.js first, then admin.js
  • Initialization: renderAdmin() called after auth check

🔗 Function Call Chain Examples

Example 1: User Adds Item to Cart

User clicks "Add to Cart" button ↓ handleShopClick() triggered ↓ changeCart(id, 1) called ↓ getCart() → getItems() → Validates stock ↓ Updates cart entry (qty++) or creates new entry ↓ saveCart(cart) → Persists to localStorage ↓ updateCartCount() → Refreshes badge ↓ renderShop() → Re-renders with updated cart indicators

Example 2: Admin Updates Price

Admin enters new price in input field ↓ Admin clicks "Save" button ↓ saveItem(id) triggered ↓ getItems() → Finds specific item ↓ Updates item.price with new value ↓ saveItems(items) → Persists to localStorage ↓ showToast() → Success notification
